# Hooks OpenSpec Commit y Code Rules

Categoría: arquitectura · Afecta: [html](../html/), [css](../css/), [js](../js/)

## Qué

Se implementan los dos hooks definidos en `AGENTS.md`:

- **OpenSpec Commit** es un hook de git (`pre-commit`) que bloquea un commit si no añade una nota nueva en `openspec/decisiones/<categoria>/NNN.md`.
- **Code Rules** es un hook de Claude Code (`PreToolUse` sobre `Write` y `Edit`) que bloquea la escritura de HTML, CSS o JS con `<style>` o `<script>` en línea, atributos `on*=` o `style=""`, hexadecimales fuera de `theme.css`, `var` o `console.log`.

Los dos son scripts de Node sin dependencias.

## Por qué

Una regla que vigila un hook no depende de que alguien se acuerde de ella. Hasta ahora los siete commits del proyecto cumplían la regla de OpenSpec solo a mano.

OpenSpec Commit no puede ser un hook de Claude Code, como decía `AGENTS.md`: ese hook se ejecuta antes del comando, y en `git add … && git commit` todavía no hay nada preparado, así que bloquearía siempre. Como hook de git se ejecuta en el momento justo y vigila también los commits que Pau hace a mano.

Se añade el atributo `style=""`, que no estaba en la lista, porque también es código en línea y lo prohíben las reglas globales. Las reglas de atributos solo miran dentro de una etiqueta, para no confundir variables de JavaScript como `once` con un `on*=`.

Por decisión de Pau no hay pruebas automáticas: se comprobó a mano que cada regla bloquea, que `theme.css` y los archivos actuales pasan, y que Claude Code dispara el hook.

## Archivos

- `.claude/settings.json` y `.claude/hooks/code-rules.mjs` — hook Code Rules
- `.githooks/pre-commit` y `.githooks/openspec-commit.mjs` — hook OpenSpec Commit
- `package.json` — `prepare` activa `.githooks` en cada `npm install`
- `AGENTS.md` — sección 5 y carpetas fijas
- `.gitattributes` — `.githooks/` y `.claude/` fuera de los paquetes
