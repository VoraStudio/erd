# Conexión con el CMS desde el servidor: cliente y endpoint propios

Categoría: php · Afecta: [arquitectura](../arquitectura/), [js](../js/)

## Qué

La web lee los proyectos del CMS (VoraCMS) desde el servidor. `src/CmsClient.php` pide un token presentándose con el dominio de ERD en la cabecera `Origin`, lo guarda 5 minutos en un archivo temporal y lee `/api/projectes_erd`. `src/CmsProjectes.php` convierte las entradas en lo que necesita la web, y `public/cms/projectes.php` lo entrega al navegador: sin parámetros, las tarjetas del listado; con `?id=77`, el detalle de ese proyecto.

## Por qué

- El CMS no usa claves: da un token (JWT de 1 hora) al dominio que figura en `allowed_domains` del usuario `erd`. Como ERD no tiene un proyecto propio en el CMS, la ruta pública `/api/public/{proyecto}/{tipo}` no sirve, y se usa la ruta del usuario con token, `/api/{slug}`.
- Se hace desde el servidor, como pide `AGENTS.md`: el navegador no pide el token ni conoce el CMS. Aunque la web se pruebe en local, el servidor se presenta siempre con `https://erd.cat`.
- El detalle se busca entre las entradas **publicadas** del listado y no con `/api/{slug}/{id}`, porque ese endpoint del CMS no comprueba el estado y dejaría leer borradores por su id.
- Se descartó un proxy genérico (permitiría pedir cualquier sección del CMS): el endpoint tiene el slug `projectes_erd` fijo. También se descartó llamar al CMS desde JavaScript, que dependería de CORS y expondría el flujo del token.
- Seguridad: el slug solo admite minúsculas, cifras y guion bajo; el token se valida con el formato de un JWT antes de ir a una cabecera HTTP; el id del detalle solo admite cifras; solo salen los campos que la web necesita.
- Se hizo con TDD estricto: la llamada de red se recibe como función y se prueba con un CMS falso (178 comprobaciones con `php tests/run.php`).
- Limitación conocida del CMS: `/api/event` y `/api/noticia` dan 500 porque esos slugs se repiten en varios proyectos. No afecta a `projectes_erd`, que es único; si se usan Events o Notícies hará falta crear tipos con nombre propio.
- Los textos de los recuadros del detalle (cifra incluida) son de tipo texto en el CMS, para poder escribir el signo y la unidad.

## Archivos

- `src/CmsClient.php` — token, caché y lectura de una sección
- `src/CmsProjectes.php` — convierte entradas del CMS en tarjetas y detalle
- `src/Http.php` — `responderJson` admite una cabecera de caché (por defecto, `no-store`)
- `public/cms/projectes.php` — endpoint de listado y detalle
- `tests/run.php` — pruebas del cliente y de los proyectos
